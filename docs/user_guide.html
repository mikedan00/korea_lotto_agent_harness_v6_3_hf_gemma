05AI 리뷰 모델 설정

AI 리뷰 보드는 같은 모델을 세 번 호출합니다. AI는 번호를 직접 만들거나 바꾸지 않습니다.

  1. 분석가: 최종 세트와 백테스트 결과를 해석하는 리포트
  2. 비평가: 분석가 리포트의 과장·오류·과적합을 검토해 accept / revise / reject 판정
  3. 최적화 자문: 다음 실행 파라미터 제안. 허용된 키와 범위만 반영됩니다

Hugging Face Router

  1. 사이드바 LLM 공급자에서 Hugging Face Router를 고릅니다.
  2. HF_TOKEN을 입력합니다. 비워두면 .env나 Streamlit Secrets 값을 쓰고, 입력값은 현재 세션에서만 쓰입니다.
  3. HF 모델을 목록에서 고르거나 ✏️ 직접 입력으로 조직/모델:프로바이더 형식을 입력합니다.
  4. Fallback 후보에는 1순위 모델이 실패했을 때 차례로 시도할 모델을 쉼표로 적습니다.
  5. 🔌 모델 연결 테스트로 확인합니다.

Claude Code CLI (로컬 노트북 전용)

최초 1회 설치하고 로그인합니다.

npm install -g @anthropic-ai/claude-code
claude          # 로그인 후 /exit 로 종료
claude --version
  1. claude가 PATH에 있는 같은 터미널에서 Streamlit을 실행합니다.
  2. LLM 공급자에서 Claude Code CLI (로컬)를 고르고, 초록색 "감지" 메시지를 확인합니다.
  3. Claude 모델을 고릅니다. sonnet(기본, 균형) · opus(고성능) · haiku(빠르고 저렴) · fable 또는 전체 모델 ID.
  4. CLI 타임아웃은 세 번의 호출 각각의 제한 시간입니다(기본 240초).
  5. 🔌 모델 연결 테스트에서 "Claude CLI 연결 성공"이 나오면 준비가 끝난 것입니다.

claude를 찾지 못하면 .env에 CLAUDE_CLI_PATH로 실행 파일 경로를 적으세요. 하네스는 Claude CLI의 도구를 모두 끈 상태(--tools "")로 호출하므로 파일을 읽거나 명령을 실행하지 않습니다. 요금은 로그인한 Claude 계정 기준이고, 호출 비용은 AI 리뷰 탭 아래쪽에 표시됩니다.

지표의미보는 법
holdout edge (nats)튜닝에 쓰지 않은 검증 구간에서 앙상블 확률의 로그우도 − 균등 분포 로그우도 (95% 신뢰구간 포함)신뢰구간 하한이 0보다 커야 우위가 확인된 것
holdout 평균 적중검증 구간에서 상위 6개 번호가 실제 당첨번호와 맞은 평균 개수 (95% 신뢰구간 포함)무작위 기대값은 0.8개
holdout 적중 p (단측/양측)단측: 0.8보다 큰지, 양측: 0.8과 다른지. 검증 구간만 사용단측 p가 0.05 미만이어야 무작위보다 낫다는 근거
균등 가중치 기준선14개 전략을 같은 비중으로 쓴 앙상블을 같은 검증 구간에서 평가한 값최적화 앙상블과의 차이 신뢰구간이 0을 포함하지 않아야 최적화가 의미 있음
shrunk_to_uniform검증 실패로 신호를 약하게 만들었는지True면 사실상 무작위 선택에 가까움

후보 점수 성분

score = c_prob + c_pair + c_typical + c_prime입니다. 각 성분은 점수 가중치 × 후보 집합 안에서 표준화한 z-score이고, 네 값을 더하면 score와 정확히 같습니다. 최종 세트 상세 표의 score_rank는 전체 후보 중 점수 순위입니다. 커버리지 보너스 때문에 두 번째 이후 세트는 순위가 낮을 수 있습니다.

후보 조합 구조 지표

sum 합계 · odd 홀수 개수 · high 23 이상 개수 · consecutive_pairs 연속번호 쌍 · last_overlap 직전 회차와 겹친 수 · ac AC값(서로 다른 차이 개수 − 5) · zones_used 사용한 번호대 수 · max_same_last_digit 같은 끝수 최대 개수 · prime_count 소수 개수

08Streamlit Cloud 배포

  1. 코드를 GitHub 저장소에 push합니다.
  2. share.streamlit.io에서 New app → 저장소와 브랜치를 고르고, Main file은 app.py로 둡니다.
  3. Advanced settings → Secrets에 STREAMLIT_SECRETS_TEMPLATE.toml 내용을 붙여넣고 HF_TOKEN을 실제 토큰으로 바꿉니다.
  4. Deploy를 누릅니다.
  • Streamlit Cloud에는 Claude Code CLI가 없어서 사이드바에 "미감지"로 표시됩니다. 클라우드에서는 Hugging Face Router를 쓰세요.
  • 로컬에서 Secrets를 시험하려면 .streamlit/secrets.toml.example을 .streamlit/secrets.toml로 복사해 편집합니다(커밋되지 않음).
  • 설정 우선순위: 화면 입력값 → Streamlit Secrets → .env·환경변수 → 기본값

09데이터 업데이트

  • 새 회차가 추가된 CSV를 data/에 넣고 --csv로 지정하거나, Streamlit에서 업로드합니다.
  • CSV 컬럼은 회차, 추첨일, 당첨번호1~6, 보너스입니다. 한글·영문 컬럼명과 UTF-8·CP949 인코딩을 자동으로 인식합니다.
  • 동행복권 공나온순서 XLS(HTML 표 형식)도 올릴 수 있으며, 같은 회차는 나중에 읽은 파일 값으로 덮어씁니다.
  • 불러올 때 번호 범위(1~45), 본번호 중복, 보너스 중복을 검사하고, 오류가 있으면 실행이 멈춥니다.
